# GeoFA plugin for QGIS

[![Tests](https://github.com/GeoDanmarkGeoFA/QGIS_Plugin_GeoFA/actions/workflows/tests.yml/badge.svg)](https://github.com/GeoDanmarkGeoFA/QGIS_Plugin_GeoFA/actions/workflows/tests.yml)

> All of GeoFA's datasets in QGIS 3.34+ and QGIS 4: for viewing by anyone, and for editing with a GeoFA login.

The plugin adds the datasets of GeoFA (Geografiske Fagdata i GeoDanmark) to QGIS, styled as in GeoFA's webmap, without setting up any connections. It is for municipal GIS staff, consultants and everyone else working with GeoFA data in QGIS. The plugin's user interface is in Danish.

## What it does

- **All 80 datasets of the GeoFA specification**, in the specification's 13 groups. They are in the **GeoFA** menu and the **GeoFA panel**: search by name or theme code (e.g. `5800`), tick a dataset to add it and untick it to remove it. Icons show whether a dataset holds points, lines or polygons.
- **Styled like the webmap**: symbols and labels from GeoFA's webmap.
- **Forms**: every field has a readable alias with the field name in brackets, e.g. *Facilitettype (facil_ty_k)*, on the tabs *Generelt*, the dataset's own fields and *Øvrige felter*. Long descriptions written in HTML are shown formatted, and edited as text.
- **Code lists straight from GeoFA**: dropdowns are filled with GeoFA's current code lists when a layer is added and when a project is opened. If a code list can't be read, the field shows the codes, and the user is told which list failed.
- **Photos**: datasets with photos in GeoFA (e.g. 5800–5802, 5607, 6122, 6204, 6205) show links to them on a *Fotos* tab, and 5800 and 5802 also a link to a GPX file. The links open in the browser. The tab only appears for objects with photos, so it's never in the way while editing.
- **Only the area in view is downloaded**, so large datasets stay quick.
- **Municipality filter**: choose a municipality under *Område* in the settings, and every GeoFA layer shows only the objects inside it. GeoFA's server does the filtering, as in Danmarks Miljøportal's plugin.
- **Production and test environment**: layers from GeoFA's test environment get "[TEST]" in their name and can sit beside layers from production.
- **Viewing for anyone, more with a login**: without a GeoFA login the plugin is a viewer, and GeoFA sends only the objects marked public (`off_kode` 1). With a login (municipalities and other data owners) and *Brug mit login* ticked (the person button in the panel), layers also show the objects kept from the public that the login may see (`off_kode` 3 for all authorities, 2 for the responsible one; e.g. protection rooms) and can be edited through WFS-T. Photo links come only without the login: the plugin reads GeoFA's photo-link versions anonymously. The password is kept in QGIS's password store, never in projects or settings, and new objects get the user id and authority filled in. Removing the login in QGIS makes the plugin read-only at once.
- **Older projects keep working**: layers from version 0.36 are pointed at the renamed datasets 5608 and 5609, and **GeoFA › Opdater formularer og kodelister** gives them the new forms.

## Using it

1. In QGIS, open **Plugins › Manage and Install Plugins**, search for **GeoFA** and click **Install**.
2. Open **GeoFA › GeoFA-panel** and tick the datasets you want.
3. To see non-public objects and edit, enter your GeoFA login under **GeoFA › Indstillinger …** (or in QGIS's **Indstillinger › Indstillinger › GeoFA**) and tick *Brug mit login*. To get a login, write to [support@geopartner.dk](mailto:support@geopartner.dk).

More about GeoFA, and guides (in Danish): [geodanmark.dk – GeoFA](https://www.geodanmark.dk/home/vejledninger/geofa/).

## Development

Developer language is English (code, comments, documentation); the plugin's user interface is Danish.

| Folder | Contents |
|---|---|
| [`geofa_plugin/`](geofa_plugin) | The plugin. `layers/` (catalogue, styles and symbols) is generated by `tools/generate_layers.py`; `layers/municipalities.json` by `tools/fetch_sources.py --municipalities` |
| [`geofa_plugin/test/`](geofa_plugin/test) | Offline tests: no network, a throwaway QGIS profile |
| [`tests/e2e/`](tests/e2e) | End-to-end checks in real QGIS windows against GeoFA (reading only, no login) |
| [`tools/`](tools) | Source fetching, the generator, the release ZIP, the guide's screenshots, and checks of code lists, the webmap and secrets |
| `dev/` | Local copies of the sources, test profiles and reports. Not committed |

Run the commands from the repository root with OSGeo4W: `python-qgis.bat` is QGIS 4, `python-qgis-ltr.bat` is QGIS 3.44 LTR.

### Tests

```
python-qgis.bat -m unittest discover -s geofa_plugin/test -t .
python-qgis-ltr.bat -m unittest discover -s geofa_plugin/test -t .
```

GitHub runs the offline tests on every push and pull request, in QGIS 3.44 and 4.2 ([`tests.yml`](.github/workflows/tests.yml)).

The end-to-end check installs the plugin's release files in a new QGIS profile and tries them in QGIS 3.44 and 4: adding layers, the panel, code lists, photo links, the municipality filter, the test environment, *Opdater* and closing QGIS. With `-Zip` it installs a built release ZIP instead.

```
powershell -ExecutionPolicy Bypass -File tests\e2e\run_e2e.ps1
powershell -ExecutionPolicy Bypass -File tests\e2e\run_e2e.ps1 -Zip dev\dist\GeoFA-<version>.zip
```

It reads from GeoFA's production and test environments without a login. Failures in the test environment are reported as warnings, as it isn't always available.

### Layers and styles from the GeoFA specification

The catalogue, forms and styles are generated; don't edit them by hand. The sources are the [GeoFA specification](https://confluence.kds.dk/display/GS/GeoFA-specifikation) and GeoFA's [Database repository](https://github.com/GeoDanmarkGeoFA/Database) (datasets, fields, and which code list each field uses), GeoFA's webmap (styling) and GeoFA's production service (field lists). The values in the code lists are read by the plugin at runtime.

```
git clone --depth 1 https://github.com/GeoDanmarkGeoFA/Database dev/spec/Database
git clone --depth 1 https://github.com/GeoDanmarkGeoFA/Grafik dev/spec/Grafik
python-qgis-ltr.bat tools/fetch_sources.py
python-qgis-ltr.bat tools/fetch_sources.py --production-details
python-qgis-ltr.bat tools/fetch_sources.py --authorities
python-qgis-ltr.bat tools/fetch_sources.py --photo-layers
python-qgis-ltr.bat tools/generate_layers.py
```

`--photo-layers` records which datasets GeoFA has in a photo-link version (schema `fkg_foto_gpx_link`), per environment: read-only layers are loaded from those, and the generator gives their photo fields a link and a *Fotos* tab.

The municipality outlines for the municipality filter are built from GeoFA's own boundaries, and written straight into the plugin (`geofa_plugin/layers/municipalities.json`):

```
python-qgis-ltr.bat tools/fetch_sources.py --municipalities
```

Each outline is widened by a margin (50 m or more) and simplified by the same margin, so nothing inside the municipality is left out, and so the filter fits in a request URL (GeoFA's server turns down URLs over ~8,190 characters).

Run the generator with QGIS 3.44, so the styles load in QGIS 3.34 and later and in QGIS 4. It stops if a source above is missing. It writes `geofa_plugin/layers/` and a report of differences between the specification, the webmap and production in `dev/reports/difference_report.md`. The Danish field aliases are in [`tools/field_aliases.json`](tools/field_aliases.json).

Useful checks:

- `python-qgis.bat tools/code_lists_live.py` reports whether every code list can be read from GeoFA.
- `python-qgis-ltr.bat tools/webmap_compare.py` puts the plugin's layers and the webmap side by side in `dev/reports/compare/`.

### Releasing

1. Run the offline tests and the end-to-end check.
2. Update `version` and `changelog` in `geofa_plugin/metadata.txt`.
3. If the panel, menu, settings or forms changed, take the guide's screenshots again (QGIS shows on screen for about a minute; the images go to `geofa_plugin/Vejledning/`), and update [the guide](geofa_plugin/GeoFA_plugin_vejledning.md):
   `powershell -ExecutionPolicy Bypass -File tools\guide_screenshots.ps1`
4. Build the ZIP for plugins.qgis.org: `python-qgis.bat tools/build_zip.py` writes `dev/dist/GeoFA-<version>.zip`, a folder `geofa/` with the contents of `geofa_plugin/` without `test/`, `Vejledning/`, hidden files such as `.env`, and compiled Python. It checks the files for secrets first.
5. Run the end-to-end check on the ZIP: `powershell -ExecutionPolicy Bypass -File tests\e2e\run_e2e.ps1 -Zip dev\dist\GeoFA-<version>.zip`
6. Check the whole history for secrets: `python tools/secret_scan.py` (in OSGeo4W's shell, where git isn't on the PATH, add `--git "C:\Program Files\Git\cmd\git.exe"`).
7. Upload the ZIP at [plugins.qgis.org](https://plugins.qgis.org/) and tag the release commit (`v<version>`).
